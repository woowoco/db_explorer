# Phase 7 — AI Providers Real Implementation (2026-08-20)

## Scope

Phase 7, `db_explorer_app` projesinin AI Query Assistant modülünü mock'tan gerçek
implementasyona taşır. Üç provider (Local llama.cpp, Remote Ollama, OpenAI-compatible)
artık gerçek paketler üzerinden inference yapar; güvenlik katmanı (write/DDL guard +
schema-only context) tüm provider'lar için paylaşılır.

## Kararlar (Decisions)

### D1 — Paket seçimi

| Provider | Paket | Versiyon | Gerekçe |
|---|---|---|---|
| Local GGUF | `llm_llamacpp` | ^0.3.1 | Cross-platform (Android/iOS/macOS/Win/Linux), isolate-based (UI thread bloklanmaz), exception hierarchy zengin (`ModelLoadException`, `BackendInitException`, `InferenceException`) |
| Shared types | `llm_core` | ^0.3.2 | `llm_llamacpp` `LLMMessage`/`LLMRole`/`LLMChunk` tiplerini buradan re-export eder |
| Remote Ollama | `ollama_dart` | ^2.5.0 | Pure-Dart (no dart:ffi), `client.chat.createStream()` type-safe, NDJSON streaming |
| OpenAI-compatible | `openai_dart` | ^8.0.0 | trevorwang flavour, sealed `ChatMessage`, Chat Completions + Responses + streaming, strict semver |

Araştırma notları: `memory/phase-7-ai-package-research.md`.

### D2 — Mock'tan gerçek implementasyona geçiş

Phase 1'deki mock provider'lar `Future.delayed(...)` ile sahte yanıtlar üretiyordu.
Phase 7'de bu mock'lar **tamamen silindi**, gerçek paketlerin streaming API'leri ile
değiştirildi. Tüm provider'lar `AiCompletion` döndürür; output parse işlemi (kod
bloğu çıkarma + write/DDL post-scan) tek noktada (`AiPromptBuilder.parseCompletion`)
uygulanır.

### D3 — Schema-only context garantisi

Tüm provider'lar sistem prompt'unu `AiPromptBuilder.systemPrompt()` üzerinden kurar;
context olarak yalnızca `DatabaseSchemaSummary` (db adı, koleksiyon adları, alan
adları + tipleri + indeksler) kullanır. **Hiçbir belge değeri, hiçbir credentials
context'e dahil değildir** (brief madde 14). Kullanıcı mesajındaki olası hassas
pattern'ler (kredi kartı, SSN, vb.) `AiPromptBuilder._mask()` ile `[REDACTED]`'e
çevrilir.

### D4 — Defense-in-depth (iki katmanlı yazma niyeti reddi)

1. **Preflight (giriş kapısı)**: `AiPromptBuilder.preflight()` kullanıcı mesajını
   `_writeKeywords` listesi (`insert into`, `drop table`, `delete from`, `update`,
   `alter`, `truncate`, `create index`, vb.) için tarar. Eşleşme varsa
   `AiCompletion(warnings: ['Write/DDL query rejected by AI safety policy'])` döner
   ve HTTP/LLM bağlantısı kurulmaz.
2. **Post-completion scan (çıkış kapısı)**: `parseCompletion()` model çıktısındaki
   kod bloğunu aynı keyword listesiyle tekrar tarar. Model güvenlik talimatlarını
   ignore edip INSERT/DROP üretirse burada reject edilir.

### D5 — Test seam (factory injection)

Üç provider da constructor'da opsiyonel factory parametre kabul eder:
- `LocalLlamaCppProvider(repositoryFactory: ...)`
- `OllamaRemoteProvider(clientFactory: ...)`
- `OpenAiCompatibleProvider(clientFactory: ...)`

Production'da factory `null` kalır → gerçek paket client'ı kurulur. Testlerde
factory inject edilerek native binary / gerçek HTTP çağrısı olmadan sözleşme
doğrulanır. Bu sayede `flutter test` Windows'ta CMake toolchain'i olmadan çalışır.

## Güvenlik (Brief Madde 11, 14)

| Gereksinim | Karşılama |
|---|---|
| AI asla otomatik sorgu çalıştırmaz | Provider'lar yalnızca `AiCompletion` (öneri) döner; `DatabaseProvider.execute()` çağrısı yapmaz |
| AI asla INSERT/UPDATE/DELETE/DROP/ALTER/CREATE INDEX üretmez | Defense-in-depth (preflight + post-scan) + system prompt HARD RULES |
| Database credentials AI context'ine ASLA girmez | `AiContext` schema-only; endpoint/apiKey YALNIZCA provider constructor'ında (LLM'in görmediği yer) |
| AI context = schema-only | `AiContext` + `DatabaseSchemaSummary` + `CollectionSchemaSummary` + `FieldSchemaSummary` value alanı içermez; `parseCompletion` post-scan çıktıyı da tarar |
